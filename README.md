# Support RAG Bot — основа базы знаний

Поисковый сервис для будущей интеграции с `bot_crm`. В этом репозитории есть загрузка и разбиение документов, векторное хранение в Qdrant, BM25 + семантический поиск и независимый `POST /search`. Генерация ответа и Telegram остались отдельными: выбор основной LLM на поиск не влияет.

## Быстрый старт

Рекомендуется Python 3.12. Команды для PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-embeddings.txt
Copy-Item .env.example .env
docker compose up -d
python -m scripts.index_documents
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

Модель embeddings из `EMBEDDING_MODEL` загружается при первом запуске и может потребовать интернет и несколько минут. Далее она работает локально. Qdrant доступен только на `127.0.0.1:6333`; HTTP API также нужно запускать только на localhost. Если `data/knowledge` пуст, индексатор сообщит `documents: 0`, а поиск вернёт `results: []`.

На macOS/Linux используйте `python3 -m venv .venv` и `source .venv/bin/activate`. Запуск без embeddings нужен только для офлайн-тестов: `python -m pip install -r requirements.txt`.

## Как добавить источник и утвердить его

1. Поместите `.md`, `.txt`, `.html` или PDF с текстовым слоем в `data/knowledge`. Не помещайте туда сырые выгрузки. Пример структуры метаданных: [`examples/instruction.md`](examples/instruction.md). Для TXT, HTML и PDF запишите те же поля в соседний файл `<имя файла>.meta.yaml`, например `guide.pdf.meta.yaml`.
2. Новый материал имеет статус `draft`. Проверьте оригинал, актуальность версии и точность инструкции. Укажите `source_url`, если есть, и дату последней проверки `verified_at: YYYY-MM-DD`.
3. После профильной проверки смените `status` на `approved`. Без `verified_at` утвердить документ нельзя. Для снятия с клиентского поиска поставьте `deprecated`.
4. Запустите `python -m scripts.index_documents` снова. Изменённые чанки обновятся, устаревшие удалятся, неизменные не будут переиндексированы. Индексатор синхронизирует всю коллекцию с содержимым каталога, поэтому используйте одну коллекцию на один набор документов.

Идентификатор документа можно задать полем `document_id`; иначе он стабильно вычисляется из относительного пути. Для сохранения ID после переименования файла задавайте `document_id` явно. Хеш содержимого, ID чанков, название, категория, производитель, модель, версия, URL, тип источника, даты, статус, раздел и страница PDF хранятся в payload Qdrant. Точные дубликаты текста удаляются при загрузке; при совпадении предпочтение получает утверждённый документ. Сканированные PDF без текстового слоя требуют отдельного OCR и получают понятную ошибку.

Категории свободные: например `kkt`, `fn`, `ofd`, `marking`, `tspiot`, `egais`, `edo`, `accounting`, `services`, `faq`.

## Поиск и API

```powershell
python -m scripts.search "не отправляются чеки в ОФД"
Invoke-RestMethod http://127.0.0.1:8000/search -Method Post -ContentType 'application/json' -Body '{"query":"ФН 235","top_k":5,"filters":{"category":"fn"}}'
```

Ответ: `results` — список объектов с `text`, итоговым fusion `score`, отдельными `semantic_score` и `lexical_score`, `metadata` с `document_id`, `source`, `source_url`, `section`, `page`, `status` и остальными полями. Оценки служат ранжированию; они **не являются вероятностью правильного ответа**. Пустой список означает отсутствие достаточно релевантных утверждённых фрагментов.

Фильтры: `category`, `manufacturer`, `model`, `version`, `source_type`, `document_id`. Статус через API не задаётся: клиентский поиск всегда ограничен `approved`. Лимиты: запрос 1–500 символов, `top_k` 1–20; FastAPI отдаёт схему по `/docs`.

Для `bot_crm` достаточно вызвать `POST /search`, передать вопрос и фильтры, а в ответе использовать текст фрагментов и ссылки на оригиналы. При пустом `results` CRM должна передать вопрос специалисту или запросить уточнение. Никаких изменений в `bot_crm` этот репозиторий не делает.

**Безопасность при развёртывании:** локальный сервер и Qdrant слушают только loopback. Перед внешним доступом поставьте reverse proxy с TLS, сервисной авторизацией, ограничением сетевого доступа и журналированием; не публикуйте напрямую порт Qdrant или API. В этом PR внешняя авторизация и production-развёртывание не реализованы.

## Демо и старый бот

Семь исходных файлов в `data/docs` — учебные, не проверенные специалистом. Для отдельного демо-индекса:

```powershell
python -m scripts.index_documents --demo
python -m scripts.search --demo "ФН 235"
$env:RAG_DEMO_MODE="1"
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

По умолчанию демо-коллекция `knowledge_demo` отделена от клиентской `knowledge_v1`. Не задавайте одинаковый `QDRANT_COLLECTION` для обеих. `RAG_DEMO_MODE=1` показывает черновики и предназначен только для локального просмотра.

`AnswerService`, OpenRouter fallback, Telegram и `cli_test.py` сохранены. По умолчанию они используют утверждённый поиск Qdrant; для прежнего локального MVP можно явно задать `RAG_BACKEND=legacy_demo`, после чего `python cli_test.py` и `python bot.py` работают с учебными TXT/MD. Команда Telegram `/reload` в Qdrant-режиме не запускает индексацию: её выполняет оператор через скрипт.

## Тесты и настройка

```powershell
python -m pytest -q
```

Тесты работают без Docker, внешней LLM и сетевой embedding-модели: используют локальный Qdrant и фейковый embedding. Набор запросов для будущей оценки: `data/evaluation_questions.jsonl`. Он пока демонстрационный и должен быть дополнен реальными проверенными обращениями.

Параметры в `.env.example`: `QDRANT_URL`, `QDRANT_COLLECTION`, `EMBEDDING_MODEL`, `RAG_DEMO_MODE`, а также настройки Telegram/OpenRouter. При смене embedding-модели с другой размерностью создайте новую коллекцию и проиндексируйте документы заново. BM25 в этой версии рассчитывается по payload чанков, выгруженных из Qdrant при запросе; для большой базы следующим шагом нужен отдельный постоянный лексический индекс и калибровка порогов на реальных обращениях. Порог релевантности и словарь разговорных формулировок находятся в `app/retrieval.py`.

Скрипт `scripts/scrape_urls.py` оставлен для черновых экспериментов. Он не публикует материалы автоматически в клиентский индекс. Секреты храните только в `.env`, который исключён из Git.
