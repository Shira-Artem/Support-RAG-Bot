# Support RAG Bot — основа базы знаний

Поисковый сервис для будущей интеграции с `bot_crm`. В этом репозитории есть загрузка и разбиение документов, векторное хранение в Qdrant, BM25 + семантический поиск и независимый `POST /search`. Генерация ответа и Telegram остались отдельными: выбор основной LLM на поиск не влияет.

## Быстрый старт

Рекомендуется Python 3.12. Команды для PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-embeddings.txt
Copy-Item .env.example .env
docker compose up -d
python -m scripts.index_documents
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

## Экспертная проверка через Telegram (Windows 11)

1. Установите Python 3.12 и Docker Desktop. В PowerShell из корня проекта:

   ```powershell
   py -3.12 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements-embeddings.txt
   Copy-Item .env.example .env
   ```

2. В `.env` укажите `TELEGRAM_BOT_TOKEN` и числовые Telegram ID проверяющих в `EXPERT_TELEGRAM_IDS`, разделяя несколько ID запятыми. Для первого запуска через Groq выставьте:

   ```dotenv
   LLM_PROVIDER=groq
   GROQ_API_KEY=ваш_ключ_Groq
   GROQ_MODEL=openai/gpt-oss-20b
   GROQ_REASONING_EFFORT=low
   TELEGRAM_BOT_TOKEN=токен_бота
   EXPERT_TELEGRAM_IDS=ваш_числовой_Telegram_ID
   ```

   Откройте файл командой `notepad .env`. Ключи вставляйте только в локальный `.env`. OpenRouter остаётся доступен через `LLM_PROVIDER=openrouter`, `OPENROUTER_API_KEY` и `OPENROUTER_MODEL`.

3. Проиндексируйте проверенные документы и запустите бота:

   ```powershell
   docker compose up -d
   docker compose ps
   Invoke-RestMethod http://127.0.0.1:6333/collections
   python -m scripts.index_documents
   python bot.py
   ```

   Qdrant должен работать до запуска бота. В рабочем режиме используются документы `approved`; явный demo-режим допускает черновики, которые ещё должен проверить специалист. Если поиск ничего не нашёл, сохраняется `no_context`. Эксперт может оценить также отказ или отсутствие инструкции — это часть опыта клиента. Технические сбои провайдера сохраняются отдельно как `error`; их оценки не смешиваются с качеством содержания. Прерванные запросы переходят в `error` при следующем запуске; предполагается один локальный процесс polling.

4. Специалист отправляет `/expert`, начинает или продолжает сессию и выбирает «Получить ответ». В новом наборе 54 независимых вопроса; старые сессии сохраняют свой набор. После ответа доступны оценка 1–10, несколько кнопок типов ошибок и свободный комментарий. Все действия сохраняются немедленно. Можно пропускать, возвращаться, выбирать любой вопрос и завершить частично. «Источники RAG» показывает сохранённые фрагменты; повтор технически сбойного запроса сохраняет отдельную попытку. Подробности и подключение других специалистов по Telegram ID: [инструкция](docs/expert-testing.md).

5. Результаты сохраняются немедленно в `data/evaluations/expert_reviews.sqlite3`. У специалиста есть постоянный внутренний `specialist_id` и отдельный `telegram_id`. Новая проверка создаёт отдельную сессию. Ответ, фрагменты, источники, провайдер, модель, статус, время ответа и токены при наличии хранятся вместе с вопросом; изменение оценки не меняет исходный ответ. SQLite и экспорты исключены из Git. Для статистики и экспорта:

   ```powershell
   python -m scripts.expert_report
   python -m scripts.expert_report --export
   ```

   Файлы `expert_reviews.csv`, `expert_sessions.csv` и `expert_reviews.json` появятся в `data/evaluations/exports/`. В выгрузке по попыткам есть отдельные входные, выходные, общие, reasoning и cached tokens, время, RAG-фрагменты, размер контекста, API ID, источники и оценка стоимости. Экспорт сессий и JSON содержат групповые суммы и средние. В отчёте строится прогноз на 100 запросов в сутки и 3 000 в месяц. Для GPT-OSS 20B отдельно показывается **оценка по платным ставкам Groq**, не фактическое списание и не стоимость бесплатного тарифа. Значение `NULL` от API сохраняется как `NULL`, reasoning и cached tokens не прибавляются к totals повторно. Отчёт также показывает оценки, проблемные категории, причины ошибок и сравнение сессий. Фильтр одного проверяющего: `--expert-id 123456789`. Для другой базы или каталога вывода доступны `--db` и `--output-dir`.

6. Токены, effort, факт вызова API и полная диагностика доступны в локальном отчёте и экспортах. Поля, которых провайдер не вернул, остаются пустыми; клиентский режим токены не показывает.

Набор `data/evaluation_questions.jsonl` содержит 54 сценария: первые 30 сохранены, добавлены 24. Ожидаемое поведение требует проверки специалистом. Отдельные 30 синтетических диалогов (46 сообщений) и явный прогон через настоящие Qdrant/LLM описаны в [порядке проверки помощником](docs/assistant-review.md). Эти данные сами по себе не обучают модель.

Модель embeddings из `EMBEDDING_MODEL` загружается при первом запуске и может потребовать интернет и несколько минут. Далее она работает локально. Qdrant доступен только на `127.0.0.1:6333`; HTTP API также нужно запускать только на localhost. Если `data/knowledge` пуст, индексатор сообщит `documents: 0`, а поиск вернёт `results: []`.

На macOS/Linux используйте `python3 -m venv .venv` и `source .venv/bin/activate`. Запуск без embeddings нужен только для офлайн-тестов: `python -m pip install -r requirements.txt`.

## Как добавить источник и утвердить его

1. Поместите `.md`, `.txt`, `.html` или PDF с текстовым слоем в `data/knowledge`. Не помещайте туда сырые выгрузки. Пример структуры метаданных: [`examples/instruction.md`](examples/instruction.md). Для TXT, HTML и PDF запишите те же поля в соседний файл `<имя файла>.meta.yaml`, например `guide.pdf.meta.yaml`.
2. Новый материал имеет статус `draft`. Проверьте оригинал, актуальность версии и точность инструкции. Укажите `source_url`, если есть, и дату последней проверки `verified_at: YYYY-MM-DD`.
3. После профильной проверки смените `status` на `approved`. Без `verified_at` утвердить документ нельзя. Для снятия с клиентского поиска поставьте `deprecated`.
4. Запустите `python -m scripts.index_documents` снова. Изменённые чанки обновятся, устаревшие удалятся, неизменные не будут переиндексированы. Индексатор синхронизирует всю коллекцию с содержимым каталога, поэтому используйте одну коллекцию на один набор документов.

Идентификатор документа можно задать полем `document_id`; иначе он стабильно вычисляется из относительного пути. Для сохранения ID после переименования файла задавайте `document_id` явно. Хеш содержимого, ID чанков, название, категория, производитель, модель, версия, URL, тип источника, даты, статус, раздел и страница PDF хранятся в payload Qdrant. Точные дубликаты текста удаляются при загрузке; при совпадении предпочтение получает утверждённый документ. Сканированные PDF без текстового слоя требуют отдельного OCR и получают понятную ошибку.

Категории свободные: например `kkt`, `fn`, `ofd`, `marking`, `tspiot`, `egais`, `edo`, `accounting`, `services`, `faq`.

## Поиск и API

```powershell
python -m scripts.search "не отправляются чеки в ОФД"
Invoke-RestMethod http://127.0.0.1:8000/search -Method Post -ContentType 'application/json' -Body '{"query":"ФН 235","top_k":5,"filters":{"category":"fn"}}'
```

Ответ: `results` — список объектов с `text`, итоговым fusion `score`, отдельными `semantic_score` и `lexical_score`, `metadata` с `document_id`, `source`, `source_url`, `section`, `page`, `status` и остальными полями. Оценки служат ранжированию; они **не являются вероятностью правильного ответа**. Пустой список означает отсутствие достаточно релевантных утверждённых фрагментов.

Фильтры: `category`, `manufacturer`, `model`, `version`, `source_type`, `document_id`. Статус через API не задаётся: клиентский поиск всегда ограничен `approved`. Лимиты: запрос 1–500 символов, `top_k` 1–20; FastAPI отдаёт схему по `/docs`.

Для `bot_crm` достаточно вызвать `POST /search`, передать вопрос и фильтры, а в ответе использовать текст фрагментов и ссылки на оригиналы. При пустом `results` CRM должна передать вопрос специалисту или запросить уточнение. Никаких изменений в `bot_crm` этот репозиторий не делает.

**Безопасность при развёртывании:** локальный сервер и Qdrant слушают только loopback. Перед внешним доступом поставьте reverse proxy с TLS, сервисной авторизацией, ограничением сетевого доступа и журналированием; не публикуйте напрямую порт Qdrant или API. В этом PR внешняя авторизация и production-развёртывание не реализованы.

## Демо и старый бот

Семь исходных файлов в `data/docs` — учебные, не проверенные специалистом. Для отдельного демо-индекса:

```powershell
python -m scripts.index_documents --demo
python -m scripts.search --demo "ФН 235"
$env:RAG_DEMO_MODE="1"
python -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

По умолчанию демо-коллекция `knowledge_demo` отделена от клиентской `knowledge_v1`. Не задавайте одинаковый `QDRANT_COLLECTION` для обеих. `RAG_DEMO_MODE=1` показывает черновики и предназначен только для локального просмотра.

`AnswerService`, OpenRouter fallback, Telegram и `cli_test.py` сохранены. По умолчанию они используют утверждённый поиск Qdrant; для прежнего локального MVP можно явно задать `RAG_BACKEND=legacy_demo`, после чего `python cli_test.py` и `python bot.py` работают с учебными TXT/MD. Команда Telegram `/reload` в Qdrant-режиме не запускает индексацию: её выполняет оператор через скрипт.

## Тесты и настройка

```powershell
python -m pytest -q
```

Тесты работают без Docker, внешней LLM и сетевой embedding-модели: используют локальный Qdrant и фейковый embedding. Они также проверяют сохранение и возобновление экспертной сессии, доступ, повторное оценивание, экспорт, ошибки генерации и изоляцию вопросов. Сценарии `data/evaluation_questions.jsonl` требуют последующего утверждения главным специалистом.

Параметры в `.env.example`: `QDRANT_URL`, `QDRANT_COLLECTION`, `EMBEDDING_MODEL`, `RAG_DEMO_MODE`, а также настройки Telegram/OpenRouter. При смене embedding-модели с другой размерностью создайте новую коллекцию и проиндексируйте документы заново. BM25 в этой версии рассчитывается по payload чанков, выгруженных из Qdrant при запросе; для большой базы следующим шагом нужен отдельный постоянный лексический индекс и калибровка порогов на реальных обращениях. Сопоставление задачи, сервиса и достаточности доказательств описано в [retrieval pipeline](docs/retrieval-pipeline.md).

Скрипт `scripts/scrape_urls.py` оставлен для черновых экспериментов. Он не публикует материалы автоматически в клиентский индекс. Секреты храните только в `.env`, который исключён из Git.

## Свободный диалог и экспертный режим

Управление состоянием обновлено: [архитектура и миграция SQLite](docs/dialogue-state.md).
После ручного теста Telegram просмотр обращений: `python scripts/show_last_conversation.py` (для полного контекста добавьте `--context`).
Telegram и CLI используют инкрементальный `DialogueState`; запрос строится из задачи,
сущностей и требований, а не склейкой сообщений. Офлайн-трассировка:
`python -m scripts.trace_dialogue_state --full`.

`/start` и `/menu` открывают выбор режима. Свободный диалог сохраняется в
`data/conversations.sqlite3`: `conversations` — отдельные диалоги владельца в чате,
`chat_state` — выбранный режим и текущий диалог, `messages` — полные сообщения
клиента и бота. В `messages.diagnostics_json` сохраняются поля `Answer`: модель,
провайдер, сценарий, исходный ответ, найденные фрагменты, токены, длительность и
причины отказа/ошибки. Незавершённые ответы помечаются при перезапуске.

«Новый диалог» и `/clear` переключают на новый ID, не удаляя переписку. Для LLM
передаются структурированные факты клиента и ожидаемое уточнение. Прежние ответы
бота не используются как факты. Смена темы исключает старое обращение из поиска,
смена сервиса сохраняет задачу и требования. Экспертные сессии,
наборы вопросов и оценки 1–10 остаются отдельно в `data/evaluations/expert_reviews.sqlite3`.

Поиск учитывает заголовки статей и код ошибки, отбирает сервис до ранжирования
и подхватывает соседние разделы статьи. Проверка ответа выполняется до отправки:
неподтверждённые фрагменты удаляются с сохранением подтверждённых сведений; опасные фискальные инструкции блокируются. Повторного вызова LLM нет. Блокировка
`.local/bot.lock` допускает только один процесс polling; файл удалять не нужно.
