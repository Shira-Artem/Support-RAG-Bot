# aQsi Online и 1С: границы интеграции по API

## Когда применимо
Вопрос относится к облачной услуге aQsi Online и обмену с 1С. Не применяйте к ней процедуру «aQsi Интегратор» для физической ККТ: отдельная инструкция производителя описывает локальный обмен ККТ aQsi по протоколу ККМ Offline 3.1 или Штрих-М.

## Что подтверждено производителем
Официальная страница облачного API перечисляет методы создания и обновления отложенных заказов, кассиров, товаров, магазинов и категорий, а также получение списка чеков и магазинов. Отдельная инструкция для прямого подключения aQsi Online предлагает API или готовый модуль CMS и рекомендует запросить тестовую среду.

## Безопасный порядок уточнения
1. Подтвердите, что у клиента именно облачная касса aQsi Online, и назовите конфигурацию/версию 1С и нужные объекты обмена.
2. Запросите у aQsi и разработчика 1С подтверждение готового модуля либо объёма разработки по API для этой конфигурации. Просмотренные страницы не подтверждают готовый модуль для 1С:УНФ и не устанавливают его совместимость.
3. До продуктивного подключения согласуйте доступ к тестовой среде, набор методов, права, сертификат и порядок перехода. Инструкция aQsi говорит сгенерировать ключи, отправить ключ оператору и запросить сертификат, но не уточняет в читаемом тексте, какой файл/часть пары передавать и по какому каналу. Сначала подтвердите эти детали у производителя; приватный ключ и пароль к нему не отправляйте.

## Ограничения
Материал не задаёт шагов интерфейса 1С, конфигурации API-клиента, модели аутентификации или готового подключения к 1С:УНФ. Если производитель или разработчик не подтвердил схему, передайте вопрос специалисту; не подменяйте облачный API-интеграцией физической ККТ.
