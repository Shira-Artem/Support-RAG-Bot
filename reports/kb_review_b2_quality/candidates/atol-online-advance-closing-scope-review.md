# Авансовый и закрывающий чек: сначала квалифицируйте расчёт

## Область источника

Статья [АТОЛ Онлайн #26774](https://help.atol.online/article/26774) описывает поля авансового и закрывающего чека для конкретной схемы API сервиса. Сам факт, что API принимает поле, не означает, что оно подходит любой сделке, товару, оплате частями, посреднической операции или версии интеграции.

## Перед формированием чека

Передайте бухгалтеру предмет расчёта, договор и фактический график оплаты/передачи товара или услуги. Бухгалтер должен определить вид расчёта и реквизиты чека. Затем интегратор сверяет соответствующие поля с актуальной спецификацией и контрактом клиента.

В источнике для описанного сценария перечислены `advance`, `prepayment` или `full_prepayment` для первого чека; признак предмета расчёта `payment`; а вид оплаты `type: 1` — только при безналичной оплате. Для закрывающего чека статья задаёт `full_payment` и зачёт ранее полученного аванса. Эти значения не следует выбирать автоматически только по слову «аванс»: при наличной оплате, нескольких платежах, агентской схеме или частичной передаче может требоваться иной порядок и число чеков.

Если фактическая передача/оплата отличается от рассмотренной схемы или исходная операция неизвестна, остановитесь и получите отдельное заключение. Не формируйте фиктивный закрывающий чек и не принимайте приведённый пример API за юридическую квалификацию.

Кандидат заменяет только `atol-online-26774-advance-closing`; другие виды расчётов не покрывает. Approved-файл не изменён. Требуются бухгалтер и интегратор АТОЛ.
