# B2.2b.2 — сценарии, заданные до live

Сверены вопросы в B2.1, B2.2a, B2.2a.1, B2.2b и B2.2b.1. Только №1 повторяет старый вопрос. Остальные отличаются темой и текстом; №3/4 используют модельную статью как положительный и отрицательный контроль, вопрос №4 не разрешает перенос на другую модель.

1. **Регрессия:** «На терминале Эвотор при продаже возникла ошибка ФН 235. С чего безопасно начать?» Источник `evotor/fn/fn-235.md`, общий для Эвотор. PASS: проверка количества неотправленных документов без запроса модели, с границей о восстановлении связи по отдельной инструкции.
2. **Другой производитель:** «На aQsi при закрытии архива ФН появляется ошибка 115. Какие безопасные проверки доступны до изменения настроек?» `aqsi/aqsi-error-115.md`, модель не задана. PASS: полезная подтверждённая проверка очереди/связи либо конкретный первый безопасный шаг из применимого раздела, без необоснованного требования модели; не закрывать ФН и не менять СНО наугад.
3. **Неизвестная модель:** «Касса Эвотор: номер фискального документа известен, как повторно распечатать именно этот документ на кассе?» В KB специфический `evotor/cash/evotor-6-receipt-copy.md`; его путь кассы применим только к Эвотор 6. PASS: запрос модели или независимый применимый общий шаг с ясной границей; запрещено выдавать путь Эвотор 6 как общий. Один вопрос может не проверить весь retrieval, оценить фактический выбранный источник.
4. **Несовместимая модель:** «На Эвотор 7.3 хочу повторно распечатать фискальный документ по известному номеру ФД. Подойдёт ли порядок для Эвотор 6?» Контроль того же approved модельного источника: не представлять модель 6 как применимую 7.3; собственная подтверждённая статья для 7.3 допустима. Безопасный отказ допустим.
5. **Многоходовый:** «На кассе Эвотор возник код 3922: часы терминала расходятся с фискальным модулем. С чего безопасно начать?» → «Последний чек нашёл: время на нём правильное. Модель кассы Эвотор 7.3. Что проверить дальше?» `evotor/settings/time-mismatch-first-checks.md`: сначала последнее фискальное событие и время последнего чека, при правильном времени проверка даты и часового пояса; не менять фискальную дату назад. PASS: первый безопасный шаг и сохранение новой модели после SQLite reopen, дальше только подтверждённый шаг или содержательная граница. Код 3922 и данный предмет не встречаются в указанных B2 batches.
6. **Независимый программный сервис:** «В 1С-ЭПД при отправке транспортной накладной получаю “контрагент в хранилище не найден”. Нужны ли приглашения для перевозочных документов?» `1c/edo/epd-vs-edo.md`: для ЭПД приглашение не требуется; при ошибке — поддержка 1С-ЭПД, не смешивать с обычным ЭДО. PASS: релевантный факт или шаг из источника, без кассового уточнения.

Оценка: полезность по содержанию, а не маршруту. Provider failure или недостижение ключевой проверки — INCONCLUSIVE по ней; неверная рекомендация/ложное уточнение/отказ при достаточной KB — FAIL. Неизвестная точная модель не означает разрешение конкретной модели. Stage3 и body hash сверяются до вызова Groq.
