# Активная база знаний и воспроизводимость retrieval

Активная коллекция Qdrant: `knowledge_sprint_v1_20261022_quality_gate`. На момент экспорта `get_collection` и два независимых чтения `scroll` дали 927 точек, 269 уникальных `document_id`, вектор Cosine размерности 384. Все 269 документов имеют `status=draft`; активный процесс работает с `demo_mode=true`. В обычном режиме фильтр `approved` исключил бы эти документы.

`knowledge/manifest.json` содержит для каждого документа исходный `document_id`, относительный `source`, путь к обезличенному полному тексту, число и упорядоченный список `chunk_id`, метаданные Qdrant, исходный `content_hash` и SHA-256 выгруженного текста. `knowledge/chunks.jsonl` содержит текст и полный payload каждого чанка; `knowledge/vectors.jsonl` — исходные 384-мерные векторы. Это позволяет соединить сохранённые `retrieval_diagnostics` с фактическими кандидатами и воспроизвести dense ranking без вызова модели эмбеддингов. Сырые идентификаторы Qdrant сохранены, поскольку они описывают документы и чанки, а не Telegram-пользователей.

Проверка источников: для каждого из 269 документов найден файл в `data/knowledge`; `DocumentLoader` вычислил тот же `content_hash`, а `Chunker` — те же `chunk_id` и тексты, что хранятся в активной коллекции. Исходные файлы не копировались побайтно: архив содержит нормализованный текст после `DocumentLoader`, чтобы включить содержимое HTML/PDF и убрать front matter из текста. Маскирование персональных реквизитов может изменить экспортный SHA-256, поэтому исходный `content_hash` сохранён отдельно. Метаданные коллекции — фактическое состояние Qdrant; актуальность, официальность и достоверность самих материалов этим не подтверждаются.

Связь: `retrieval_by_answer.jsonl` → `retrieval_diagnostics` → `document_id` / `chunk_id` → `manifest.json` и `chunks.jsonl` → полный текст `documents/*.txt`. Манифест фиксирует `source_url`, тип источника, производителя, модель, категорию, дату публикации/проверки/сбора и статус там, где эти поля были в Qdrant. Результаты retrieval — сохранённые результаты реально состоявшихся ответов; новых поисковых запросов при экспорте не запускалось.
