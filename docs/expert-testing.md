# Экспертная проверка в Telegram

Откройте `/expert` или «Экспертное тестирование». Доступ остаётся закрытым: Telegram ID должен быть в `EXPERT_TELEGRAM_IDS` локального `.env`. Разные люди используют свои Telegram-аккаунты: чужая сессия и оценки им недоступны. Не передавайте общий аккаунт и ключи бота.

Чтобы добавить специалиста, попросите его отправить боту `/whoami` и передать полученное число администратору. Администратор добавляет ID через запятую к существующему списку `EXPERT_TELEGRAM_IDS` в локальном `.env`, например `EXPERT_TELEGRAM_IDS=123456789,987654321`, сохраняя остальные ID. Настройка загружается при старте; для применения оператор перезапускает только этот экземпляр бота. Изменять `.env` или перезапускать бот во время текущей доработки не требуется. ID — идентификатор человека, не секретный токен; токен бота никому передавать не нужно.

В новом наборе 54 вопроса: первые 30 сохранены с прежними ID, добавлены 24 независимых сценария по ККТ/ФН, ОФД, aQsi Online, АТОЛ Онлайн, Эвотору, маркировке и ЭДО. Формулировки синтетические; ожидаемое поведение составлено по локальным карточкам. Это не проверенные эталоны и не автоматическое обучение модели. Большинство карточек имеют статус draft и нуждаются в проверке специалистом. Старые сессии сохраняют свой исходный набор; для новых вопросов начните новую сессию.

1. Выберите вопрос и нажмите «Получить ответ». Это настоящий запрос к текущему провайдеру и модели. Каждый вопрос независим; обычный разговор проверяйте через «Свободный диалог».
2. Оцените ответ: 1 — не помогает или неверен, 5 — требует существенных исправлений, 10 — корректен и полезен. Оценивайте также уточнения, отказы и отсутствие инструкции, поскольку их получает клиент.
3. При желании отметьте несколько ошибок кнопками. Повторное нажатие снимает отметку. Затем добавьте свободный комментарий: какой шаг неверен, чего не хватает и как ответить правильно. Комментарий можно исправить повторным вводом через ту же кнопку.
4. Переходите дальше, пропускайте, возвращайтесь назад или выбирайте любой вопрос из списка. Переходы и просмотр источников не вызывают LLM повторно. Для технического сбоя есть отдельная кнопка повторного запроса; старая попытка остаётся в базе.
5. Можно остановиться в любой момент. Ответ записывается сразу после получения, оценка — при нажатии числа, каждая метка — при нажатии, комментарий — при отправке. Завершать весь набор не требуется. `/expert` предложит продолжить незавершённую сессию после перезапуска.

Кнопка «Источники RAG» показывает сохранённые фрагменты отдельным сообщением. Диагностика, исходный текст модели, итоговый ответ, статус проверки, модель, effort и токены сохраняются в экспертной SQLite. Обычная история диалогов не подменяет экспертные оценки. Технические сбои сохраняют отдельный статус и не должны использоваться как правильные/неправильные содержательные ответы при подготовке обучающей выборки.

«Закончить сейчас» завершает сессию, сохраняя частичный результат. Новая сессия не удаляет старую. Пропущенный вопрос не считается оценённым. Несколько оценённых попыток одного вопроса считаются одним вопросом в прогрессе.

В отчёте отдельно указаны число оценённых вопросов и число попыток. Средние баллы рассчитываются по содержательным оценённым попыткам; оценки технических сбоев показаны отдельно. Локальную выгрузку можно получить командой `.\.venv\Scripts\python.exe -m scripts.expert_report --export`.

Схема дополняется новыми полями попыток и таблицей `review_tags`; старые таблицы, свободные причины `reviews.reason`, оценки и комментарии не удаляются и не переписываются. Автоматически переучивать модель или публиковать синтетические ответы в Qdrant этот режим не умеет и не должен.
