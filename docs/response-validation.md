# Ответы в пределах подтверждённых сведений

`AnswerService` отвечает на текущую операцию, а не на все темы найденной статьи. Релевантность retrieval не означает, что документ подтверждает каждую деталь ответа модели.

`app.response_grounding` обрабатывает ответ локально, без дополнительной генерации:

1. Фискальная опасность проверяется для всего ответа. Если обнаружена опасная инструкция, вся последовательность заменяется направлением к специалисту, даже если источник описывает её.
2. Остальные замечания относятся к отдельным утверждениям или шагам. Названия элементов интерфейса, заявленные действия, названия ролей и их полномочия проверяются отдельно. Общий процент совпавших слов предложения больше не служит основанием для отказа.
3. Независимые прошедшие проверку утверждения сохраняются. Если один шаг смешивает известные и неподтверждённые действия, вместо него можно использовать дословное подходящее утверждение источника. Оно должно целиком присутствовать именно в отправленном модели контексте и пройти те же проверки.
   Для конкретной процедуры одного совпавшего глагола недостаточно: он не подтверждает поля, параметры и обещанные результаты. Такие шаги восстанавливаются из действий источника даже без выдуманной кнопки. Это режим точного изложения процедуры, а не утверждение, что любое перефразирование ошибочно. Уникальный родительский раздел можно восстановить только из той же статьи.
4. Полномочия связываются с конкретной ролью и локальным отрицанием: права другой роли или запрет другой операции не подтверждают утверждение. Администратор как исполнитель процедуры не доказывает существование роли с таким названием.
5. Отсутствие матрицы прав не отменяет инструкцию создания пользователя. Описание меню существующей записи можно сообщить отдельно от отсутствующего порядка настройки прав. Неподтверждённое название роли не предлагается пользователю.
6. При отсутствии подходящей инструкции возвращается обычный ответ без внутреннего поискового запроса. Полные причины остаются в диагностике.

Это ограниченный детерминированный контроль, не полноценная семантическая проверка любого русского текста. Он не восстанавливает сведения, которых нет в базе. При расширении словаря действий и полномочий нужны регрессии на источниках; нельзя ослаблять фискальный запрет ради большей доли принятых ответов.

## Диагностика

В JSON каждого нового ответа свободного диалога дополнительно сохраняются:

- `reasoning_effort`: настройка провайдера для этого обращения;
- `llm_call_attempted`: факт попытки вызова, включая завершившийся ошибкой API;
- `response_repair`: режим обработки, сохранённые и удалённые утверждения с причинами, использованные подтверждения с источниками.
- `generation_error`: безопасный HTTP-статус, тип ошибки и числовой `Retry-After`, без тела ответа провайдера и секретов.

`raw_model_text`, исходные токены и API ID остаются без изменений. Полезный исправленный ответ имеет `generation_status=generated`, `validation_status=modified`; полный отказ по безопасности — `rejected`. Дополнительных попыток генерации нет, токены не суммируются повторно. Исторические JSON не переписываются: старый `reasoning_effort` показывается как «не сохранён».

Просмотр истории работает на стандартной библиотеке Python, в UTF-8, с SQLite в режиме read-only:

```powershell
python scripts/show_last_conversation.py --turns 5 --context
```
