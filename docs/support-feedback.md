# Оценки и запрос специалиста в свободном диалоге

После каждого ответа свободного диалога Telegram показывает кнопки «👍 Помогло», «👎 Не помогло» и «👨‍💻 Позвать специалиста». Код кнопки содержит внутренний `messages.id` ответа. Обработчик сверяет владельца ответа с Telegram user/chat. Экспертный режим не изменён.

«Помогло» и «Не помогло» записываются в `feedback_events` без LLM. Повторное нажатие той же оценки не создаёт вторую запись. После «Не помогло» пользователь может оставить комментарий отдельной кнопкой или продолжить диалог новым вопросом. Комментарий сохраняется на выбранном событии оценки; следующая реплика считается комментарием только после явного нажатия этой кнопки. Последняя оценка конкретного ответа учитывается в отчёте; отсутствие нажатия не считается оценкой.

Запрос специалиста сначала создаёт `support_requests` со статусом `pending_confirmation`. Подтверждение переводит его в `saved`, повторное подтверждение не создаёт новую заявку. Отмена переводит в `cancelled`. Таблица `escalation_events` фиксирует действия и состояние. Заявка ссылается на conversation, исходный вопрос и ответ; подробная диагностика остаётся в существующей записи ответа. События хранят только короткую retrieval-сводку и ID документов. Канал доставки специалисту пока не настроен; статус `delivered` не устанавливается, и клиенту не сообщается о передаче. CRM не используется.

Отчёт без содержимого переписки: `python -m scripts.support_report`. Локальная очередь сохранённых заявок с вопросом, ответом и причинами: `python -m scripts.support_queue`. Очередь читает исходные сообщения по ID и не создаёт их копий в БД.

Подробная локальная выгрузка для анализа RAG: `python -m scripts.export_support_feedback --output-dir .local/exports/support-review`. Она читает SQLite без записи и создаёт `feedback_events.jsonl`, `feedback_events.csv` и `problem_dialogues.jsonl`. Записи связаны с ID диалога, вопроса и конкретного ответа; включают время оценки, комментарий, найденные документы, исходный и финальный ответ, причины отказа и статус заявки. Файлы могут содержать текст обращений клиентов, поэтому хранятся локально в `.local` и не публикуются.

## Ручная проверка после разрешённого перезапуска бота

1. В Telegram открыть «Свободный диалог» → «Новый диалог» и задать «Где посмотреть отчёты по кассам после замены ФН в АТОЛ Онлайн?». Ожидается раздел «Отчеты по кассам», регистрационная почта, ссылка на источник и три кнопки.
2. Нажать «👎 Не помогло». Проверить предложение уточнить вопрос и продолжить текстом. Нажать «👍 Помогло» на том же ответе: отчёт должен учитывать последнюю оценку.
3. Нажать «👨‍💻 Позвать специалиста», затем «Отмена». Убедиться, что заявка не сохранена как подтверждённая. Повторить и нажать «Подтвердить» дважды: должна существовать одна заявка `saved`, `delivered` остаётся 0.
4. Задать вопрос без подтверждённой инструкции и переформулировать его без новых существенных данных. Ожидается предложение новой детали или специалиста вместо дословного повтора отказа; заявка без подтверждения не создаётся.
5. Проверить `python -m scripts.support_report` и строки `feedback_events`, `support_requests`, `escalation_events` в `data/conversations.sqlite3`. Экспертное тестирование проверить только на отсутствие изменений в кнопках и поведении.

Рабочий Telegram-процесс не перезапускается этим изменением. Новые обработчики начнут работать только после разрешённого перезапуска.
