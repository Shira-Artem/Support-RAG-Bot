# B+ Evidence Relevance / Subtask Coverage — frozen 24-attempt experiment

**Дата:** 27.10.2026. **Решение:** offline gate **NO-GO**; Telegram worker не переключался.

## Метод и ограничения

Использованы 24 обезличенные локальные записи production, frozen Resolver replay и новый replay с gate на локальном Stage3/Qdrant/SourceFirst. Planner в обоих offline replay — детерминированная локальная fixture, выбирающая первый содержательный раздел; Groq не вызывался. Это измеряет итоговые ответы кода в контролируемом воспроизведении, но не восстанавливает исторический planner из live production. Для случая #11 raw Understanding вернул HTTP 400, поэтому offline replay невозможен; сохранён фактический production ответ. Полные фактические ответы, документы/разделы, ID, quality labels и latency находятся в [обезличенной JSON-матрице](../../experiments/architecture_recovery_audit/bplus_evidence_relevance_24_three_way_20261027.json).

## Причинный разбор исходных двух ошибок

- **#9, сканер aQsi:** Resolver-only допускал периферию по общей задаче `configure_peripheral`; у весов был больший lexical rank, но их fragment не покрывал scanner. Planner fixture взял первый содержательный раздел про весы; renderer скопировал его точно и SHA/grounding не нарушил. Gate оставляет scanner section `Подключение и первое подключение` и ответ даёт безопасную проверку подключения. Причинный этап: coarse task/operation compatibility + retrieval ranking; отсутствие subject coverage между retrieval и planner было последним отсутствующим барьером; renderer не причина.
- **#22, сбой интеграции АТОЛ Онлайн:** В замороженном исходном вопросе нет явного слова API; это проблема с запросами с сайта и отсутствующими чеками. Resolver-only трактовал широкое `integration` как применимость каталога CMS/банков; lexical rank каталог поставил выше API теста, а fixture planner выбрала каталог. Renderer скопировал источник без искажения. Gate отклоняет catalog и API article при недостаточной подтверждённости точной подзадачи и эскалирует/уточняет, вместо выдуманного действия. Причина: широкая applicability + retrieval ranking без конкретной subtask coverage; не renderer.
