# Oracle RAG — изолированный эксперимент (23.10.2026)

Цель: проверить `openai/gpt-oss-20b` с полной историей текущего обращения и заранее выбранными правильными approved-источниками без LexicalAnalyzer, старых task/operation gates, ранних отказов AnswerService и extractive repair. Генерация и ручная оценка разделены. Это oracle evidence test способности модели, **не** тест retrieval или production-бота.

## Повторение

Из корня репозитория:

```powershell
.\.venv\Scripts\python.exe experiments/oracle_rag/cli.py smoke
.\.venv\Scripts\python.exe experiments/oracle_rag/cli.py run --max-calls 15 --output experiments/oracle_rag/my-run.json
```

`prepare` и `smoke` эквивалентны: проверяют конфигурацию, manifest, локальные approved-файлы, соответствие сервиса и Qdrant status для всех chunks выбранных document ID. Никаких Groq-вызовов. `run` выполняет максимум 15 вызовов, 18-секундную паузу между ними, не повторяет ошибочные запросы и не перезаписывает существующий результат. На provider error оставшиеся ходы обозначаются `unexecuted`. Требуются доступные `.env`/Groq и локальная Qdrant Stage3; ключ в результат не попадает. Входы — только синтетические, без персональных данных. Письма/телефоны/ключи, если всё-таки появятся в ответе, редактируются перед сохранением; это отражается в ограничении raw trace.

Текущий зафиксированный прогон: [исходные результаты](results.json), [результаты с независимой оценкой](reviewed-results.json), [критерии до запуска](criteria.md), [сценарии](scenarios.json), [оценки и причины](scorecard.json), [таблица](score-table.md), [отчёт](report.md). `review.py` присоединяет отдельно подготовленные оценки к копии raw результатов, сохраняет hash исходного JSON и SHA каждого ответа; не изменяет ни один ответ.

## Границы

Oracle evidence взят из локальных approved Markdown, а Qdrant использовался только для read-only сверки ID/status/service. В БД обнаружены соответствующие разделы этих четырёх документов. A получает статью после уточнения DirectBank; B и C — прямые статьи; D не получает источник; E получает только статью о тарифе конкретной ККТ после называния Платформы ОФД. Статьи о юридическом сроке договора и точной дате оплаченного периода в этом наборе нет; такой пробел нельзя считать ошибкой retrieval.

Строгие условия эксперимента зафиксированы в `criteria.md`. Два последних хода каждого обращения — сконструированные уточнения, а не реальные клиентские сообщения. Критерий «решено» требует безопасного, подтверждённого продвижения к исходной задаче; вежливый вопрос не считается решением. Результат не переносится автоматически в Telegram.
