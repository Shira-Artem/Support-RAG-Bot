# P1 D1 live gate — подготовка, не запуск

Дата подготовки: 2026-10-26. Gate не запускался: пользователь разрешил offline E2E и подготовку отдельного ограниченного Groq/Qdrant gate. Этот файл вместе с [`scripts/p1_d1_live_gate.py`](../../scripts/p1_d1_live_gate.py) фиксирует воспроизводимый single-conversation эксперимент.

## Scope и бюджет

- Два последовательных сообщения: `Что такое ОФД?` → `А зачем он нужен кассе?`.
- Максимум **2 Groq HTTP calls**: по одному `understand_message` на реплику; этот endpoint делает один HTTP attempt и не повторяет запрос. При ошибке второго шага gate останавливается.
- Для Groq Understanding существующий код задаёт `max_completion_tokens=4096` на запрос. Gate суммирует фактический provider usage и не запускает Composer, Planner, Repair или Judge: grounded information ответ B собирается из одной exact approved фразы.
- Максимум **2 hybrid retrieval turns** по существующему Qdrant collection. Перед запуском выполняются read-only проверки существования и непустоты collection. Retriever делает semantic search и lexical corpus read; число низкоуровневых Qdrant scroll pages зависит от размера collection.
- **0 Telegram calls, 0 worker actions, 0 Qdrant writes, 0 KB changes, 0 user SQLite writes.** История хранится во временной SQLite внутри `TemporaryDirectory`; существующая Understanding logger добавит записи в `.local/conversational-understanding.jsonl`, без API key.

## Запуск

Сначала убедиться, что активная среда уже настроена на `RAG_ENGINE=source_first`, Groq provider, доступный non-empty `QDRANT_COLLECTION` и требуемую пользователем allowlist-конфигурацию. Не редактировать `.env`. Флаг выставлять только в процессе gate:

```powershell
$env:AI_COORDINATOR_ENABLED = "1"
python scripts/p1_d1_live_gate.py --execute
Remove-Item Env:AI_COORDINATOR_ENABLED
```

Без `--execute` runner печатает только безопасный preflight и budget, сетевых вызовов не делает. Он не импортирует `bot.py`, чтобы исключить подключение к пользовательской SQLite, создание worker или polling.

## Pass / stop

`PASS` только если оба Understanding payload валидны, состояние после reopen SQLite на втором ходе сохраняет ту же задачу, coordinator выдаёт `grounded_information/continue` и фокус второго хода, retrieval предоставляет approved source, оба ответа проходят exact quote/SHA/independent safety gates, ответы различны и ни один не требует generative stage после Understanding. Любой timeout, HTTP/validation error, пустая/недоступная collection, missing evidence, route mismatch, unsafe/unsupported sentence, repeated answer или бюджетный overflow даёт `NO-GO`/stop; повторно не вызывать в этом gate.

Артефакт команды содержит только вопросы, ответы, coordinator decision, approved source/section, call counts и usage; ключи и headers не сериализуются. Результат gate — только свидетельство этого двухходового сценария, не пилот и не разрешение переключить worker. Для следующих P1 технических сценариев нужен новый отдельный bounded gate.
