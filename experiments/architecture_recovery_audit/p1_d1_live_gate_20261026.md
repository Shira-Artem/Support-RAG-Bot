# P1 D1 live gate protocol and execution record

Дата: 2026-10-26. Scope: один conversation `D1.2 → D1.3`, настоящие Groq Understanding и read-only Qdrant Hybrid Retrieval. Бюджет на run: максимум 2 Groq requests, максимум 2 retrieval turns, no retries, no Composer/Planner/Repair/Judge. Runner: [`scripts/p1_d1_live_gate.py`](../../scripts/p1_d1_live_gate.py).

## Защитные ограничения runner

- Только явно настроенная `QDRANT_COLLECTION`; отсутствующая конфигурация блокирует gate (без fallback к `knowledge_v1`).
- Qdrant facade разрешает только `collection_exists`, `get_collection`, `scroll`, `query_points`. Создание коллекции, upsert и delete недоступны.
- Runner не импортирует `bot.py` и не подключается к worker/Telegram/production SQLite. История живёт во временной SQLite.
- `AI_COORDINATOR_ENABLED=1` и выбор тестовой коллекции задаются только для процесса. `.env` не редактируется.
- Groq Understanding — максимум один HTTP attempt на ход. После route mismatch gate останавливается до retrieval/дополнительной генерации.
- Embedding загружается локально; перед загрузкой runner включает process-local `HF_HUB_OFFLINE=1`.
- Raw structured/validated Understanding, state, CoordinatorDecision, retrieval candidates/evidence, answers, checks, latency, calls и usage пишутся в UTF-8 trace; credentials/headers не сериализуются.

## Диагностика и фактическая конфигурация

Первая попытка завершилась connection refused до Groq, потому что существующий `rag-qdrant-1` был остановлен. Он относился к проектному `docker-compose.yml` и сохранял volume `rag_qdrant_storage`; контейнер безопасно запущен без recreate/reindex. В Docker Desktop контексте `desktop-linux` подтверждено локальное опубликование `127.0.0.1:6333`.

Последние успешные live tests проекта использовали `knowledge_stage3_retrieval_20261022` (см. состояние от 2026-10-25 в [PROJECT_STATE](../../docs/PROJECT_STATE.md)); именно она выбрана явной process-only переменной. В inventory: 934 points, 672 approved, 262 draft, 384 dimensions. Все 206 approved docs и их content hash/scope согласованы с локальными источниками; все 672 approved chunks совпали с локально пересобранными chunks.

В `.env` effective `QDRANT_COLLECTION` — `knowledge_organized_stage2_[redacted-number]`. Предыдущая BLOCKED trace ошибочно подписала `knowledge_v1`, увидев только default в исходном коде; это erratum: импорт `app.config` загружает `.env` до чтения переменной, поэтому fallback там не использовался.
