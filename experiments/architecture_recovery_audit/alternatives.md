# Архитектурные альтернативы

Дата: 2026-10-25. Оценки ниже — инженерные прогнозы по проверенному коду/экспериментам, не измеренные A/B результаты. Под «обычным разговором» понимаются приветствие, запрос формулировки задачи, благодарность и безопасная ориентация без технических фактов. Термины, конкретные реквизиты, права, меню, процедуры и действующее право требуют approved evidence соответствующей области.

| Критерий | A. Починить текущий Source-first | B. Разговорный координатор + маршруты по риску | C. Полностью упростить orchestration |
|---|---|---|---|
| Польза для клиента | Можно быстро снять известные scope/slot блоки; общий разговор всё ещё связан с жёсткими label gates | Наиболее вероятно улучшение: общий разговор сразу, технические ответы только по источникам, частичные безопасные проверки | Потенциально высокий потолок, но длительный период миграции без доказанной пользы |
| Галлюцинации / опасные шаги | Низкий риск технического дописывания при exact-source, остаётся неверный выбор применимой секции | Средний риск при ошибке маршрута; локальные safety gates, claim/step ledger и exact-source для действий обязательны | Высокий риск при свободном single-pass generation; Oracle показал выдуманные меню и роли даже с правильными статьями |
| Надёжность контекста | Сохраняет текущий SQLite state; нужны исправления семантических/lexical переходов | Один явный task/slot контракт, coordinator получает историю и решает связь, reducer валидирует факты | Нужно переписать/мигрировать state и доказать replay/migration заново |
| Реализация | Низкая для P0, высокая накопленная сложность | Средняя: новый routing contract на существующих store/retrieval/renderer | Высокая: новая orchestration и перестройка тестов |
| LLM-вызовы | 0 для social, до ~5 для information, 2 для exact technical path плюс Understanding | Цель: 0–1 social, 1–2 обычная информация, 2–3 технический путь; требуется измерить, не гарантия | Цель 1–2, но цена независимой safety проверки может вернуть вызовы |
| Задержка / стоимость | Наиболее предсказуемая реализация, но 9 вызовов/13 352 токена в двухходовом live объяснении уже зафиксированы | Ожидаемое снижение на частых общих ходах; дополнительная стоимость координатора оправдана, если заменяет несколько stage | Потенциально меньше вызовов, но высокие затраты разработки и риск повторных прогонов |
| Расширение тем | Множатся aliases, `task_category`, special gates и metadata crosswalk | Новые approved карточки + риск/тип задачи; расширение taxonomies всё ещё требуется для техник | Чистый контракт возможен, но перенос всех safety исключений дорог |
| Совместимость | Максимальная, текущий worker не меняется до gate | Хорошая: хранение/поиск/approved/renderer переиспользуются; ветка за feature flag | Низкая; требует переключения production пути и миграции |

## Фактические опоры и отказ от крайностей

- Для A: Source-first способен дать полезный exact-source результат на ограниченном синтетическом наборе [evidence-first vertical](../evidence_first_vertical/report.md), но шесть живых реплик показали 0/6, а текущий repair не прошёл полный offline suite. Исправлять P0 необходимо при любом варианте. Продолжать добавлять ещё одно regex исключение на каждый пример недостаточно.
- Для B: [Oracle RAG](../oracle_rag/report.md) показал сильное понимание/удержание темы моделью при провале фактической точности (0/5 строгих решений). Это поддерживает LLM для координации, а не для безусловной технической генерации. Approved, applicability, запрет необратимых операций и независимая проверка должны остаться.
- Для C: удаление стадий выглядит привлекательным при 9 calls/2 turns, но [Model Benchmark](../model_benchmark/report.md) нашёл опасную неподтверждённую процедуру и у 120B. Снижение числа вызовов само по себе не доказывает безопасность. Полная замена также откладывает короткий диагностический пилот.

Выбор B зафиксирован в [decision.md](decision.md). Гибрид не означает свободный LLM-ответ на технические вопросы. Внутри B допустимо упрощать stages после парного измерения, но это последовательная оптимизация P3, а не немедленный переход к C.
